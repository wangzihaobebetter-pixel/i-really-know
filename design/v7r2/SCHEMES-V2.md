# 十个方案 v2 —— 每个方案是一个产品主张，不是一张皮

第一轮的十个方案是「十个对标对象各配一套外观」。这一轮换了组织方式：
**先从调研里提炼出 21 条交互模式（`PATTERNS.md`），再让每个方案回答一个不同的产品问题。**

因为你的最终目的是「**选一个方案去决定后面的功能方向**」，所以每个方案下面都写清楚四件事：

- **依据**：对标谁、多少评分人数、证据在哪个文件
- **设计逻辑**：为什么这个形状能解决那个问题
- **交互逻辑**：一次完整的「过一遍」，逐步骤写清楚每步屏上有什么、用户做什么、系统回什么
- **选它意味着什么**：如果主线走这个方案，产品后面的功能会往哪长；以及**它解决不了什么**

## 01 · 那页纸

**它回答的问题**：被追问的时候，我的原文该在哪？

**依据**：GoodNotes 443,855（`appstore2/full-goodnotes-01.jpg`：手写页在上半屏，底部面板给话题芯片与建议问题，
**页从头到尾没有被替换**）；Speechify 517,576（文本满屏 + 底部悬浮控件，实测常驻栏高 156px，动效 80–150ms）。

**设计逻辑**：这个产品叫「我真会」。要判断一个人是不是真会，唯一的依据是他自己写下的那句话。
把原文压成一个可展开的小块（我们现在是 `多看一点原文 84×40`），等于要求学生凭记忆作答——
那检验的是记忆，不是理解。**页必须是主角，问题是覆盖在它上面的一层。**

**交互逻辑**（一次完整的过一遍）：
1. 进入 → 全屏是学生自己的原文，**被追问的那一句已经画好下划线**，页面自动滚到它。顶栏只有返回、标题、`3/8`。
2. 底部升起一张 40% 高的问题面板：一行话题芯片（这份作业里站不住的几个点）+ 当前这一问。
3. 学生作答 → **页不动**，面板长高到 60%，输入框在面板里。
4. 自评三档 → 面板内切换，页仍然不动。
5. 判定回来 → **原文里那句话的下划线变色**（站住=绿、有点虚=琥珀、没站住=靛），面板给一句话判定。
6. 下一问 → 页**滚动**到下一个锚点，下划线跟着走。整场口试里，学生的视线从没离开过自己的那页纸。

**选它意味着什么**：产品后面会往「**标注 / 批注**」长——把整页做成可批注的对象（GoodNotes 的方向），
教师端也会自然变成「在同一页纸上留批注」。
**它解决不了**：手机屏上原文和面板抢空间，长材料（论文）会很挤；代码类材料横向滚动更难处理。

## 02 · 我读到的是这句

**它回答的问题**：系统凭什么问我这一句？

**依据**：GoodNotes 443,855（`full-goodnotes-04.jpg`：套索选中后浮出 `Confirm Math Recognition`，
把识别结果摊开 + 一支编辑笔，**确认之后才继续**）。

**设计逻辑**：我们从材料里定位锚点是暗箱。锚点定错了，学生看到的是一个「莫名其妙的问题」，
他会归因为**产品不行**或**自己不行**，而不会归因为「它读错了」。
**把识别结果显式地放出来让他改，一次纠正的成本远低于一次错误的追问。**
这也是十个方案里唯一把「模型可能读错」这件事写进界面的。

**交互逻辑**：
1. 交完作业 → 不直接出题。先出一屏：**「我读到这份作业里有 6 个地方站不住。」**
2. 每个地方一行：引用原文那一句 + 一句「我为什么盯上它」+ 两个动作 `✓ 是这句` / `✗ 不是，换一句`。
3. 学生可以删掉两条、改一条的引用范围（拖动选区）。**改动即时反映在下面的预览里。**
4. 确认后才生成问题，且**每个问题的开头都带着那句被确认过的原文**。
5. 过一遍时，顶部始终有一行小字：「这一问来自你确认过的第 3 处」。

**选它意味着什么**：产品会往「**可解释、可纠正**」长——每一个判定都能追溯到一句原文和一次确认。
这是最接近「学术诚信工具」的方向，也是老师最可能买单的方向。
**它解决不了**：多一个确认步骤，第一次使用的路径变长；急着用的学生会觉得啰嗦。

## 03 · 说出来

**它回答的问题**：口试为什么要打字？

**依据**：Babbel 750,907（`full-babbel-02.jpg` / `-04.jpg`：`Listen, then say it out loud`，
底部中央大号麦克风是唯一动作；`full-babbel-06.jpg`：`How would you like to review?` 让用户挑 Listening/Speaking/Flashcards/Writing）。

**设计逻辑**：Babbel 用 75 万评分证明了一件事——**只要说话不是最容易的那个动作，用户就会退回打字**。
我们对标的是「当面被追问」。打字给了学生时间组织语言，而组会上没有这个时间。
**把麦克风做成唯一的主按钮，打字降级为一个小的次要入口。**

**交互逻辑**：
1. 开始前先问一次：**「这次想怎么被考？」**——`说出来（像组会那样）` / `打字（慢慢想）` / `只看不答（先熟悉）`。
2. 选「说出来」后：问题以**大字 + 朗读按钮**呈现，屏幕中下方是一个 **72×72 的麦克风**，打字入口是它旁边一个小图标。
3. 按住说 / 点一下开始 → 波形实时反馈 → 松开即提交。**不给编辑机会**（这是特性不是缺陷：组会上你也不能重说）。
4. 自评三档。
5. 判定以**带头像的对话气泡**呈现：你说的在右，考官的判定在左。整场口试读起来就是一份转录。

**选它意味着什么**：产品会往「**口语能力 + 真实场次演练**」长——计时、追问、打断、模拟提问人。
这条线离「答辩陪练」最近，也最容易讲清楚差异化。
**它解决不了**：安静场合用不了；中文/英文混说的识别质量不确定；对口音敏感。**这条要在真机上验证过才敢主推。**

## 04 · 诚实条

**它回答的问题**：承认不会，为什么比编一个更难？

**依据**：Khan Academy 110,169（我亲手走的公开练习题，实测底栏 `[画笔][重来] "Do 4 problems" [Skip 44×40] [Check 130×40]`，
见 `OBSERVED.md`）；Elevate 539,777（`full-elevate-05.jpg`：`[Skip] [Submit]` 并排等宽）。
**两个独立产品、65 万+评分，都把逃生口放在提交旁边。**

**设计逻辑**：实测我们的「这题我会卡住」是 **78×19px**，提交钮 52×52。
界面在用尺寸告诉学生：**编一个答案比承认卡住更容易**。而编答案是这个产品唯一不能容忍的行为——
它直接摧毁我们卖的那个判断。**这不是配色问题，是当前最严重的设计缺陷。**

**交互逻辑**：
1. 底部一条常驻操作栏，从左到右：`[我卡住了 ≥44×44]` `还剩 4 问`（一句白话，不是进度条）`[提交 130×44]`。
2. 点「我卡住了」不是跳过——它进入**卡壳流程**：「那你会怎么弄清楚它？」（现有的 blank-plan），
   学生写一句方法就能继续，**这一步同样计入结果**，标记为「知道怎么查」。
3. 提交后自评、判定，回到同一条栏。栏从不移动，位置肌肉记忆稳定。
4. 结果页把「卡住但知道怎么查」单独列一栏——**它是一个正面结果，不是失败**。

**选它意味着什么**：产品会往「**诚实度本身就是一个可测量的指标**」长——
自评与判定的落差（我们已有的 calibration/divergence）成为主指标，而不是正确率。
这条线最贴产品的哲学，也最容易做出别人抄不走的东西。
**它解决不了**：它是一个交互修正，视觉个性弱——**它更应该是所有方案的地基，而不是十选一里的一个**。

## 05 · 间隔

**它回答的问题**：自评到底在承诺什么？

**依据**：Anki（间隔重复的事实标准；按钮写 `1m Again / 10m Good / 4d Easy`——**具体档位与间隔以官方手册为准，
待子代理核实后再引用**）。

**设计逻辑**：自评是一个**关于未来的承诺**，不是关于现在的形容词。
「站住了」是个形容词；「7 天后再问你」是个承诺。把后果写在按钮上，学生的选择才有依据，
也才会在第 7 天真被问到时对自己那次判断负责。

**交互逻辑**：
1. 界面极素：无卡片、无阴影、圆角 5px，字体系统体，动效 120ms。
2. 答完 → 屏幕下方一排三个按钮，每个两行：
   `站住了` / `7 天后再问` ｜ `有点虚` / `3 天后再问` ｜ `没站住` / `明天再问`
3. 选完立即显示：**「好，9 月 1 日再问你这句。」**——把承诺变成一个具体日期。
4. 首页是一张素表：作业 · 待答 · 到期。到期数字是唯一的红色。

**选它意味着什么**：产品会往「**长期记忆调度**」长——间隔算法、到期队列、跨作业的知识点合并。
这条线的天花板最高（Anki 二十年没被取代），但见效最慢。
**它解决不了**：冷启动阶段没有「到期」可显示，首页会长期是空的。

## 06 · 关卡

**它回答的问题**：我到底在为哪一场准备？

**依据**：Busuu 100,261（`full-busuu-05.jpg`：路径上一个特别标记的 `Checkpoint — Test your skills to access the next chapter`）；
Structured 164,657（横向日期条 + 纵向时间线，每格带时间与进度环）。

**设计逻辑**：我们的数据里已经有真实的场次——**组会 8/31、答辩 9/12**，还有 1/3/7 天回访。
现在它们只是卡片上的一行元数据。Busuu 的做法是把「检验」从日常练习里拎出来做成一道**门**。
对我们，那道门是现成的：**答辩就是那道门**，日常的每一遍都是在为它铺路。

**交互逻辑**：
1. 首页是一条纵向路径。路径上有两类节点：**普通节点（一次过一遍）** 和 **门（真实场次）**。
2. 门上写：`答辩 · 9 月 12 日 · 还有 18 天`，以及**「按现在的状态，你有 3 句会被问穿」**。
3. 门是灰的，直到它前面的节点做完才亮——但**永远可以跳过去**（我们不是在锁内容，是在给顺序建议）。
4. 过一遍时顶栏常驻一行：`为 9/12 答辩准备 · 第 3/8 问`。**每一问都知道自己是为哪一场服务的。**
5. 门那天到了 → 一屏总结：「明天就是答辩。这三句你上周还没站住，现在站住了。」

**选它意味着什么**：产品会往「**为一场具体的考试做准备**」长——倒计时、场次模板（组会/答辩/面试）、
临场前一晚的速览。这条线最容易让学生说清楚「我为什么现在要用它」。
**它解决不了**：没有明确场次的用户（就想自查）会觉得被强行安排。

## 07 · 今日一组

**它回答的问题**：今天做到什么程度算做完了？

**依据**：Elevate 539,777（`full-elevate-02.jpg`：`Recommended` 下一列今日项目，带类目标签与完成勾）；
Readwise（`Daily Review` 一张卡：*7 highlights from …* + 一个 Review 按钮）。

**设计逻辑**：我们的今天页现在是**入口的集合**（带一份来 / 回访 / 范例），不是**今天要做的事的集合**。
开放式产品没有终点，也就没有「做完了」的那一刻。
把今天压缩成一个**封闭集合**：今天 5 问，做完就结束，明天再来。

**交互逻辑**：
1. 首页顶部一句：`今天 5 问 · 大约 8 分钟`。下面五行，每行一问的**出处**（哪份作业的哪一句）+ 类目标签。
2. 做完一行打勾并划掉，剩余数字实时减。**做完第五行，页面变成一张完成卡**（P20，只给两行数字）：
   `你说站住了 4 句` / `其中真的站住 2 句`。
3. 那两个数字之差就是全部价值，点进去看是哪两句。
4. 已经做完的一天，首页显示「今天做完了。明天见。」——**不给更多可做的事**，这是刻意的。

**选它意味着什么**：产品会往「**每日习惯**」长——推送时间由用户定（P11）、连续天数、每日难度调节。
这条线的留存最好做，但要小心：**我们的用户不是天天有新作业的**，每日一组的内容从哪来是个真问题。
**它解决不了**：内容供给。没有新作业时，五问只能来自回访，一周后会重复。

## 08 · 解答单

**它回答的问题**：一次口试结束后留下什么？

**依据**：Gauth 1,457,502 + Photomath 732,929（一次解答 = 编号步骤清单，逐条展开）；
Chegg 204,684（`full-chegg-study-03.jpg`：等待态是 `Sent → Working → Answered` 三段线 + 一句人话 + 两个出口）。

**设计逻辑**：口试是过程，但学生需要一个**能带走的东西**。
把整场做成一份**编号解答单**：第 1 问…第 8 问，每条可展开看原文、你的原话、判定和标准。
这份东西可以打印、可以给导师看——它就是我们已经有的「可打印文档」，只是被提到了主界面。
Chegg 的等待态在这里尤其重要：**模型判定要几秒，那几秒是学生刚说完话、最紧张的时刻**，
一个转圈把它浪费了。

**交互逻辑**：
1. 过一遍时，整场以一份长清单呈现：做过的收起来打勾，当前那条展开，没到的灰着。
2. 提交后等待态不是转圈，是三段线：`收到 → 正在读你的原话 → 判定`，配一句人话。
3. 判定回来，当前条收起，下一条展开。**滚动位置不跳**。
4. 全部做完 → 这份清单就是结果页，顶上加一行汇总，右上角一个「导出 PDF」。

**选它意味着什么**：产品会往「**交付物**」长——给导师看的报告、给自己存档的记录、课程作业的附件。
这条线最容易被机构采购（老师要的是可归档的证据）。
**它解决不了**：手机上一份长清单不好读；它更像桌面产品。

## 09 · 大纲

**它回答的问题**：一学期下来这些东西怎么组织？

**依据**：Notion 89,863（实测：UI 用 `NotionInter 14/20`，**正文阅读用 `Lyon Text` 衬线 18/28**，
圆角 4–8px，hover 是一块 5px 灰矩形，没有卡片）；Notability 453,065（文档 + 自动生成的结构化章节）。

**设计逻辑**：作业 → 每一遍 → 每一问，天生是三层嵌套。
学期末学生真正需要的是「**我这学期哪些概念反复站不住**」，那是一个跨作业的视图，
卡片式布局做不到，树可以。**双字体（UI 一套 / 阅读一套）是这个方案的形式支点。**

**交互逻辑**：
1. 首页是一棵可折叠的树，没有任何卡片。三角展开，hover 一块浅灰。
2. 过一遍在树里就地展开：当前问是一个展开的节点，答完折叠打勾，下一个展开。**不换屏。**
3. 另有一个「按概念看」的切换：把所有作业里指向同一个概念的问题聚到一起。
4. 阅读原文时字体切到衬线 18/28，和界面文字明显分开。

**选它意味着什么**：产品会往「**知识图谱 / 概念追踪**」长——跨作业的薄弱点聚合，这是我们已有的
「概念地图」功能的正统归宿。
**它解决不了**：手机上折叠树的命中区和手势都很别扭（Notion 自己在手机上也退化了）。

## 10 · 卡片

**它回答的问题**：判定之前，能不能先逼我表个态？

**依据**：Quizlet 1,104,312（一张全出血卡，翻面看答案）；
Elevate 539,777（`full-elevate-06.jpg`：一句话 + `✗ ERROR` / `✓ VALID` 两个明确按钮）；
Busuu 100,261（`True or False?`）。

**设计逻辑**：我们的自评发生在**打字之后**。学生打完 200 字，已经把自己说服了。
他们的做法是**在展开之前先要一个二值判断**。
先表态、再展开说，得到的自评更干净，「自评 vs 判定」的落差也更有诊断价值。

**交互逻辑**：
1. 一张全出血卡，正面是原文那一句 + 一问。卡下面两个大按钮：`这句我站得住` / `这句我说不清`。
2. **先按一个**（此时还没打字）→ 卡翻面，露出输入区：「好，那说说看。」
3. 说完 → 判定。结果同时显示三个东西：**你按之前说的**、**你说完之后的**、**判定**。
4. 三者不一致时，产品说的是那句最重要的话：**「你先说站得住，说完之后自己改了口。」**

**选它意味着什么**：产品会往「**元认知校准**」长——测量的不是知识，是「你对自己的判断准不准」。
这是学术上最站得住、也最难被大厂顺手做掉的方向。
**它解决不了**：多一次点击；二值前置对「部分会」的情况过于粗暴。
