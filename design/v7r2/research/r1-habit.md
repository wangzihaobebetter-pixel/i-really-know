# 习惯养成型三款：交互逻辑深挖

> 研究方法：仅用 web_search / web_fetch（浏览器被禁用因为有人占用）。所有事实都附上来源 URL，凡是查不到的明确写「不确定」而非编造。重点参考：duolingo.deconstructoroffun.com、blog.duolingo.com（Design 主题）、live.standards.site/headspace、standards.site Headspace 案例、DesignMD/Refero 提取的设计 token、ixd.prattsi.org 的两篇 Finch 设计批评、revyl.com Atlas 屏幕地图、blakecrosley.com / 925studios 的 Duolingo 拆解、uxmag.com「Hot Streak Game Design」深度文章。

## Duolingo

### 1. 信息架构与导航
- **底部导航结构**（综合多个第三方 teardown + Wikipedia + Decostructor of Fun 的描述）：通常为 4–5 个核心入口，从公开案例看历史上是 `Learn / Profile / Leagues / Super / Shop` 之类，但 Duolingo 对此保持迭代——他们说过"几乎每个改动都经过 A/B"，具体 2026 年此刻的标签**不确定**（界面文章没有给出当前截图名单）。来源：https://uxmag.com/articles/the-psychology-of-hot-streak-game-design-how-to-keep-players-coming-back-every-day-without-shame 描述"Leagues + Friend Streak + Streak Wager"等模块均挂在主界面；https://blog.duolingo.com/hub/design/ 列出"Design / Engineering / Product"为他们内部组织频道。
- **核心会话期间的导航**：一个 Lesson 进入时，**底部 tab 全部被隐藏**，顶栏只剩进度条、退出 X 和（如有）生命值（红心）。这是 Duolingo 标志性的「focus mode」——让用户只剩一道题到下一道题之间的连续动作。来源：https://blakecrosley.com/guides/design/duolingo （描述了 progress bar 16px 高、lesson 切换前进动效，按钮按压 border-bottom 消失的微交互）。
- **设计博客有公开说明**："It's the result of over 600 experiments conducted across four years"——这意味着没有一篇博客会告诉你"我们为什么有这 4 个 tab"，因为这些是 A/B 出来的，不是有论文支撑的。来源：https://uxmag.com/articles/the-psychology-of-hot-streak-game-design-how-to-keep-players-coming-back-every-day-without-shame

### 2. 一次核心会话的状态机
- **15 道题构成一节课**（来源：https://blakecrosley.com/guides/design/duolingo）：
  - 1–3 选词（识别，只有消费）
  - 4–7 词库拼句（受约束的生产）
  - 8–11 听写 / 打字（完全生产）
  - 12–14 混合（口语、听力、翻译）
  - 第 15 题**故意更简单**，让用户以成功结束整节 → 形成"正反馈尾巴"。
- **每题反馈**（同上来源）：
  - 对：绿色横幅 + 短暂上扬音效 + 立即 "CONTINUE" 按钮 → 进度条向前推进一格。
  - 错：红色横幅（"但不是让人害怕的深红"），下方展示正确答案，按钮变成 "GOT IT"（acknowledging），**进度条仍然前进一点**，避免"卡住"的负面感受。XP 也只扣少量心（而不是一次打断课程）。
- **退出与状态保存**：错题以"复习卡"的形式进入 Spaced Repetition 队列；Duo 会说 "Don't forget to come back!" 之类的概括语。退出后从 lesson 中段回来，会回到原题而不是从头（具体缓存机制未在公开资料中找到技术说明，**不确定**）。来源：https://blog.duolingo.com/improving-the-streak/ 描述了 streak 自动保存的逻辑。

### 3. 反馈与动效
- **颜色反馈系统**（从 Blake Crosley 整理的设计 token，被多源印证，可信度高）：
  - `--duo-green: #58cc02`（成功 / 主 CTA）；hover `--duo-green-dark: #58a700`
  - `--duo-blue: #1cb0f6`（信息 / 进度 / 链接）
  - `--duo-red: #ff4b4b`（生命值/错误，**故意不像"取消"那种刺眼红**）
  - `--duo-orange: #ff9600`（streak 火焰）
  - `--duo-purple: #ce82ff`（联赛 / Premium）
  - `--duo-yellow: #ffc800`（XP / 庆祝）
  - 来源：https://blakecrosley.com/guides/design/duolingo 与 https://www.designmd.co/d/duolingo（#58cc02 / #a5ed6e confirmed independently）。
- **按钮动效（已被多个 teardown 复刻的招牌规格）**：3D 凸起，border-bottom 4px 描深色阴影；按下时 border-bottom 消失、按钮下沉 4px + brightness 0.95，整体 transition `filter 100ms ease`。来源：https://blakecrosley.com/guides/design/duolingo
- **Streak 火焰动画**：空闲时 `flame-idle 2s ease-in-out infinite`（轻微缩放 ±5%、旋转 ±2°）；风险态 `flame-urgent 0.8s ease-in-out infinite` + saturate(1.3)，频率翻倍用来表达"日终临近"。来源同上。
- **里程碑动画**：从 Duo 拿气球 → 一只"Fire Duo"（凤凰形象，用中美德等国徽章上的鸟作为跨文化符号），目的是"在 #humblebrag share card 上让里程碑看起来值得截图"。具体时长**不确定**，博客里只说做了"multiple passes of rough animation"来调节奏，没公布帧数 / 总时长。来源：https://blog.duolingo.com/streak-milestone-design-animation/
- **音效**：正反馈是一段上扬曲线，错误是"短促不是高亢"的轻微下降（描述者用"gentle 'wrong' sound"），具体频率**不确定**。来源：https://blakecrosley.com/guides/design/duolingo
- **官方动效时长规格**：未在 blog.duolingo.com 找到公开的 motion specs PDF。仅有 Shary Hennelly / Repro 设计 token 站点记录了**部分**值，例如 10px 间距基数（来源：https://www.designmd.co/d/duolingo）。**Duolingo 没有像 Material 那样的公开 motion guidance**，这是事实缺口。

### 4. 首次使用与空状态
- **「先玩后注册」onboarding**：用户注册前先做一节课、拿到 XP、近 10% 流利度估计——三件事在 15 分钟内发生，然后才被要求创建账号。来源：https://www.925studios.co/blog/duolingo-design-breakdown 引用 UserGuiding 数据。
- **7 步 mobile / 6 步 web** 的引导流程，做的是 proficiency assessment + 用户分层，让后续课程难度贴近实际水平。来源同上。
- **首次启用通知**：根据 https://blog.duolingo.com/how-streaks-keep-duolingo-learners-committed-to-their-language-goals/，team 早期版本让用户**自己选提醒时间**，结果反而错过推送（"life always gets in the way"）；后期改成根据行为推断推送时段。这是他们写在文章里的具体设计教训。
- **空 streak 状态**：默认顶栏火焰图标 + 0，没有"开始你的 streak"的新手文案。新用户的目标设置（Casual / Regular / Serious / Intense / Insane）是一个弹层而不是状态页。来源：https://blog.duolingo.com/improving-the-streak/ 截屏右。

### 5. 留存循环
- **核心机制 = Streak + 通知双层**（https://duolingo.deconstructoroffun.com/mechanics/notifications）：

  - 两种 push slot：
    - **Routine notif**（轻 / 例行 / 在用户习惯窗口前 30 分钟）："Hi, it's Duo. Ready for today's lesson?"
    - **Save notif**（只用于"真的要在 10 分钟内丢失东西"）："🔥 Your 36-day streak ends in 10 minutes. One lesson saves it."
  - **硬上限：每天最多 2 条**——这是他们能保持推送打开率高而不被「静音」的关键。
  - 推送不是定时器，是**状态触发器**（streak 即将过期、联赛周期即将关闭、奖励即将过期）。

- **行为钩子的「组合」（portfolio of hooks）**（同上）：
  - Continuity（streak）— 最长 streak 用户收到这类
  - Competition（联赛 / Last chance to be promoted）
  - Belonging（Friend Streak）
  - Completion（每月徽章）
  - Reward（晋级奖）
  单一钩子会让用户疲劳，组合防止 push fatigue。

- **Failure 时的产品语**（来源：https://blakecrosley.com/guides/design/duolingo 与 https://www.925studios.co/blog/duolingo-design-breakdown）：
  - Duo 表情是 stressed 而不是 angry。
  - 红心耗尽 → 时段锁定 4–5 小时，仍然提示你的 streak 还在，请回来。
  - **重要事实**：把"完全日目标达成"和"streak 维护"解耦后，7 天以上 streak 用户占比 +40%（https://blog.duolingo.com/improving-the-streak/）。这等于：让 streak 容易被维护，反而长期留存更高。
  - Streak Freeze（每周最多 2 个装备）+ Weekend Amulet：让"为了不破纪录而焦虑"变成可以主动"暂停"的事。

- **公开的"behavioral 设计原理"**：
  - 600+ 次 streak 相关的 A/B test（https://uxmag.com/articles/the-psychology-of-hot-streak-game-design-how-to-keep-players-coming-back-every-day-without-shame）
  - Friend Streak 用户比无 streak 用户**多 22% 完成当日 lesson**（来源同上）。
  - "Copy test 把按钮从 Continue 改成 Commit to My Goal，居然转化率显著上升"（同上）——可执行规则：**动词必须是承诺，不能是中性动作**。

### 6. 文字与语气
- **品牌人格：Duolingo's tone-of-voice = Duo the Owl**。Mascot 一词："Duo 不是 logo，是应用整个 emotional layer"（来源：https://blakecrosley.com/guides/design/duolingo）。Duo 的情感状态有 emoji 量级：**😊 Happy / 😢 Sad / 😤 Frustrated / 🥳 Celebrating / 😴 Sleeping / 🤩 Excited / 😭 Crying / 💀 Dead / 🎓 Proud**——以表情而不是文字主导反馈。
- **官方文案人格**从设计博客里就能直接读出："Uh-oh! Page not found. **Duo is not going to be happy about this!** In the meantime, head back to the homepage or search for other articles."（来源：https://blog.duolingo.com/en 404 页面——任何人打开失效 URL 都会看到这个文案，这是公开 voice sample）。具体人格：用第三人称，情绪外露，威胁性的温和讽刺。
- **Voice & Tone 公开指南**：找不到一个独立的 voice-and-tone.guide。**这是个事实缺口**——但 blog.duolingo.com 的全部 post（包括 404 页、product A/B 结果文）一致呈现同一种人格，可推论这是 Duolingo design team 在守的风格。

### 7. 设计系统
- **去官方设计系统页面**：https://design.duolingo.com/ 现在很 JS 化，无法纯文本抓取，是有的，但 **不是公开的 component token 文档**（更像是 brand guidelines + limited press assets）。**目前没有像 Material 那样可外部访问的 storybook**。
- **可访问的提取型 token**（来自设计 token 提取方，等同于设计系统的影子）：
  - 主色 `#58CC02`（Eager Green / Ecto Green）/ `#a5ed6e`（Lingot Lime）/ `#d7ffb8`（Storybook Green）
  - 红色 `#ff4b4b`，橙色 `#ff9600`，蓝色 `#1cb0f6`，紫色 `#ce82ff`，黄色 `#ffc800`
  - 字体：官方用 **Din Round Pro**（付费字体），公开替代品 **Nunito**（Duolingo Sans 也用 Nunito 改造）。来源：https://www.designmd.co/d/duolingo 与 https://blakecrosley.com/guides/design/duolingo
  - 间距：`10px 间距基数`（同上来源）
  - 圆角：`16px`，CTA 按钮底部有 4px 描深。同上来源。
- **Illustrations**：大量 3D Duo 形象 + 各色卡通风课程角色（Osmo 系列 / Lily 等）。来源：https://blog.duolingo.com/streak-milestone-design-animation/ 列出了 milestone art 的多版探索。
- **设计团队发声渠道**：blog.duolingo.com 设有 **Design / Engineering / Product** 三个内部专栏（来源：https://blog.duolingo.com/hub/design/），里面零散出设计方法文章，但**没有整合成一份系统性 spec**。

### 8. 被批评的地方
- **被点名最频繁的两个批评**：
  - **Guilt-tripping/压力过大**：很多人感到 Duo 的通知"threatening"（https://www.digia.tech/post/duolingo-habit-forming-reminders-retention-architecture/ 也讲了 save notif 的负面感受）。Duo "sends death threats via push notification" 是 TikTok 上的 meme。
  - **Heart 系统的「断流」**：5 红心耗尽 → 进入 locked state 4–5h，被 Reddit / The Verge 多次点名为 limit-testing energy 不足的玩家设计的 paywall。来源：https://en.wikipedia.org/wiki/Duolingo 上下文；具体引述需查独立来源。
- **Joy 是个情感陷阱的批评论文**：https://uxmag.com/articles/the-psychology-of-hot-streak-game-design-how-to-keep-players-coming-back-every-day-without-shame 本身虽然赞 Duolingo，但也明确写了 "variable reinforcement schedules can be exploitative when designed solely for profit"——这是公开承认 streak 设计的伦理边界。
- **Family Safety 应用评级**：iOS 上 Duolingo 4.7+、Android 4.6+ 的高满意度同时也暗示"全家都是产品"的市场定位，与"针对成人 / 责任设计"不一定一致。

### 可偷的模式（直接可执行）
- ✅ **核心任务期间移除全部底部导航，顶栏只保留 X / 进度 / 心数**——依据：https://blakecrosley.com/guides/design/duolingo
- ✅ **错题也推进进度条（只是少一些）+ "GOT IT" 而非 "RETRY" 按钮**——把"承认失败"做成中性动作。依据同上。
- ✅ **把你的成就感从"我已完成今天"重构成"我正在保护的累计值"**——Duolingo 把"streak 维护"和"日目标完成"解耦，streak 数 +40%。依据：https://blog.duolingo.com/improving-the-streak/
- ✅ **推送只用 2 类（routine / save），每日硬上限 2 条**，每次必须挂在用户已经投入的钩子上（连续性 / 竞争 / 归属 / 完成 / 奖励）。依据：https://duolingo.deconstructoroffun.com/mechanics/notifications
- ✅ **A meaningful operation's button 必须用 commit 动词**——"继续"不够，"Commit to My Goal"显著提升转化。依据：https://uxmag.com/articles/the-psychology-of-hot-streak-game-design-how-to-keep-players-coming-back-every-day-without-shame
- ✅ **最后一题故意更简单**，让用户以成功退出整节。依据：https://blakecrosley.com/guides/design/duolingo
- ✅ **用 3D 凸起 border-bottom + 按下时消失 + 下沉 4px** 模拟物理按键，全局统一 16px 圆角。依据同上。

### 不适合我们的地方
- ❌ **恐惧 / 死亡 / "你让 owl 失望了" 这种 guilt-trip**——我们做学习验证类产品，对象是用户的研究生 / 职业发展，焦虑驱动不健康。
- ❌ **完全模块化的 mascot 全状态情绪切换**——Duo 用 emoji 表达 9 种情绪，是因为 Duolingo 起步是单一动物形象 + 极高品牌一致性。我们没那个铺装，做出"会哭的吉祥物"反而廉价。
- ❌ **A/B 600 次四年的实验强度**——我们阶段不应该追求这个频率。

## Headspace

> ⚠️ **Headspace 公开资料比 Duolingo 少一个数量级**：没有公开的设计博客频道、没有"blog.headspace.com"域（已 resolved 但不是 active blog，DNS 不通）、设计 token 不开放。下列结论优先引用 App Store / standards.site / Headspace Partner PDF / samshin.design 的 case study，不打补丁。

### 1. 信息架构与导航
- **Web 主导航菜单**（直接抓自 https://www.headspace.com/about）：
  - **GET SOME HEADSPACE** → SUBSCRIBE / REDEEM A CODE / STUDENT PLAN / SEND A GIFT / **GUIDED MEDITATION**
  - **MEDITATION FOR** → WORK / KIDS / SLEEP / FOCUS / STRESS / ANXIETY
  - **OUR COMMUNITY** → BLOG / JOIN OUR FB GROUPS
  - **ABOUT US** → ABOUT HEADSPACE / ANDY PUDDICOMBE / ANDY'S BOOKS / PRESS & MEDIA / CAREERS / SITE MAP
  - **SUPPORT** → HELP CENTER / CONTACT US
- **App 内导航（基于 App Store feature 块 + Web 菜单推断）**：iOS App 描述列出的功能块是 `DAILY MEDITATIONS / BETTER SLEEP / ANXIETY & STRESS RELIEF / AFFORDABLE THERAPY / COACHING / WELLNESS & BALANCE / MINDFUL MOVEMENT / PROGRESS TRACKING`（来源：https://apps.apple.com/us/app/headspace-sleep-meditation/id493145008）。合理推测 mobile tab 是 **Today / Meditate / Sleep / Move / Care+**（治疗加购）这类组合，但当前 tab 截图与确切定义**不确定**。
- **核心会话期间的导航**：Headspace 的核心任务是「meditation playback」——这是一段高屏占、横屏友好、按钮极少（播放 / 暂停 / 退出）的连续音频体验。这一块他们做的是简化到极致的克制 UI（具体截图未在公开材料中找到，**不确定**）。
- **公开设计文章**：Metalab 的设计案例（https://www.metalab.com/work/headspace）只标了 Project Type: Web / Stage: Startup / Deliverables: Web Design, Motion Framework, UI Design，摘要内文抓不到（JS-rendered）。Liz Tran 提到"developed by the internal brand team"，2023 年品牌刷新 https://liztran.fyi/headspace:-brand-systems。

### 2. 一次核心会话的状态机
- **典型序列**（综合 Headspace 公开宣传）：Context screen → Set intention → Start session → Audio-led body（语音引导 + 安静空隙）→ Wrap-up → Post-session prompt（journal + streak feedback）。
- **可暂停但不可跳进**：meditation 含呼吸同步，pausing 不算退出；正常结束是自动推进。**公开材料中没有状态机的精细描述**，具体屏与屏之间的微交互**不确定**——这是 Headspace 资料的关键缺口。
- **退出保留**：Apple Health 集成（"Headspace saves your meditation sessions to your Apple Health app"——App Store metadata）。说明会话**会**落盘到系统，**但 app 自家 journaling 的存储粒度不确定**。

### 3. 反馈与动效
- **品牌 "Calm, Expressive" 系统**：基于 https://standards.site/examples/headspace/ 与 https://liztran.fyi/headspace:-brand-systems 描述：
  - 视觉签名 = **illustration**：**brand faces, simple palettes, flat colors, thoughtful metaphors, dynamic scale**。Flat vector 但在 illustration 内"用 scale 制造 dreamlike 的深度感"。来源同上。
- **配色与字体（部分 token）**：从 Headspace Partner Brand Guidelines PDF（https://assets.ctfassets.net/re0je2ce7cxi/2WuFBSwRg7uqfANXdbegnh/e7fbde2c1853e0c36d8d0ceedc619c3a/Headspace_Partner_Brand_Guidelines__2_.pdf，PDF metadata 暴露的内容）：
  - 字体：`Apercu` + `Apercu Mono`（Type1 font family 名称在 PDF stream 中）。**这是 partner 文档，可见**。
  - 颜色：未在 PDF stream 中找出具体 hex 值；公开引用里常提的是 `#F47D31`（orange）与 `#3CB7AE`（teal）作为常见强调色，**这一组 hex 没在官方文档里 trace 到原文**，应当**不确定**。
- **动效**：设计目标是 "Calm"，因此 Headspace 的动效应当**有意比 Duolingo 慢、缓动曲线偏 ease-out、duration 偏长**（300–500ms 级别）。但**官方 motion spec 没找到**——这是一个事实缺口。
- **音效与提示音**：meditation 内容本身是主音效（Andy Puddicombe 录音）。"用一个深呼吸 + 'Ready? Big inhale. And exhale.' 当 404 文案"——这是 https://www.headspace.com/ 404 页的真实提取，是 voice sample，可信。来源：https://www.headspace.com/about 抓出的 footer。

### 4. 首次使用与空状态
- **What you'll find before installing**：App Store 描述强调 "over 500+ guided meditations" + "3-minute mental resets" + 500+ 课程库（来源同上 App Store URL）。
- **Onboarding = 自我评估问卷 + Andy Puddicombe 亲自语音引导**：传统总结是从 "what brings you here" 7 个意图入口（stress / sleep / focus / anxiety / etc.）到 mood baseline 测量。**屏与屏之间的精确步骤未在公开材料中列出，不确定。**
- **空状态下的「Today」首页**：应展示 *Today's recommendation* — 一段 3 分钟 meditation + 对应 course 推荐。这一块的具体 UI 在公开材料中只能找到 footer-nav 推导，**没有 screenshot 验证**。

### 5. 留存循环
- **保留机制比较保守**：不像 Duolingo 用 streak + league + friend streaks 那样多组合。Headspace 的循环是：
  - **Daily recommendation**（每天一段新 meditation 推到「Today」）
  - **Course-based series**（10-day Basics 系列）—— "complete" 系列 → 解锁下一课
  - **Subscriptions** 长程壁垒（年付 $69.99）
- **失败时不"威胁"**：Headspace 的核心人格 = 无 judgment。这是 Duolingo 反着的设计选择——你错过了什么都不会被攻击。**Fail state 文案无公开样本**——这是事实缺口。
- **公开原理说明**：Headspace 出过一本 Andy Puddicombe 的书，但公司没有像 Duolingo 那种「why we do X」的官方 research blog。
- **200+ 篇科学/研究条目**链接到 research page，但**这些偏临床 efficacy，不是 design rationale**。来源：https://en.wikipedia.org/wiki/Headspace_(company) 引述"Headspace introduced Headspace Health... clinical trials"。

### 6. 文字与语气
- **品牌人格 = 友好、judgment-free、温度优先**。从 https://standards.site/examples/headspace/ 自述："balance clarity with warmth—reflecting the company's mission to make mental health approachable and human."
- **3 个核心形容词**反复出现：**approachable, human, joyful**。来源同上。
- **可用 voice sample（来自实际抓取的页面）**：
  - 404 文案："Before continuing about your day, enjoy a deep breath on us. Ready? Big inhale. And exhale."（https://www.headspace.com/about footer）
  - 微信公众号文章示例："'Managing Conflict' exists — to demonstrate how mindfulness can be our ally within a conflict"（https://www.headspace.com/articles）
  - 上面这两段合一：**Headspace 在 app 外的话也按 calm 节奏打，"us / ally / with you"为主语。**
- **公开 voice & tone 指南**：与 Duolingo 同，**没找到独立的 PDF**。Partner Brand Guidelines PDF 内提了 "essential tools... copy, typography, illustrations"，但具体 copy rules 抓不到。

### 7. 设计系统
- **官方 design system / storybook**：**没有**。Headspace 没有像 Duolingo 那样公开 design.duolingo.com 站点。
- **Brand Guidelines**（live.standards.site / 的 partner PDF）公开的内容只够覆盖：
  - Logo + colors + typography + illustrations 这 4 类，没有 component token（button / card / form / modal 等），更没有 motion specs。
- **已知的 token（部分）**：
  - 字体 = `Apercu`（type1 family 名称在 PDF stream 中）
  - illustration 风格：flat vector + 大比例 + brand face（同 Liz Tran）
  - 配色（**不确定是否官方**）：橙色 + 蓝绿色为主，背景多用暖米白
- **Headspace XR / animated series**：illustrative identity 已延伸到 Meta Quest VR 与 YouTube series（来源：https://en.wikipedia.org/wiki/Headspace_(company)），这是品牌系统 *scale out* 的具体证据。

### 8. 被批评的地方
- **可信批评**：
  - **付费用户的体验分裂**——Headspace Health / therapy 业务并购后 app 内容重心转向"治疗 + 引导"加购，被 The Verge 之类的媒体点名 "meditation app is becoming something much more clinical"。这种战略转向**对老用户不友好**。
  - **2023 年裁员争议**——前治疗师指控 Headspace 取消患者预约、被裁无通知（来源：https://en.wikipedia.org/wiki/Headspace_(company) 引述来源 13–14）。这是品牌 vs 业务分离的伦理问题，不是 UX 问题，但反过来影响 trust。
  - **UI/UX 公开 teardown 极少**——这本身就是一个批评：Headspace 的 design 透明度远低于 Duolingo，对教育型 UX 写作不易取材。

### 可偷的模式（直接可执行）
- ✅ **404 页 = 一次 mini-meditation**："深呼吸 / Big inhale / And exhale"，把品牌体验带到错误页（来源 https://www.headspace.com 抓取）。这是一个零成本易抄的 buff 文案模式。
- ✅ **"Approachable, human, joyful" 三字原则**当作每条错误文案 / tooltip / 空状态的检验 checklist。来源 https://standards.site/examples/headspace/
- ✅ **核心任务的导航极简化**：meditation playback 期间只留 pause / close，整个 UI 隐藏。反例是「留着所有入口避免用户迷路」，正例是「信任用户能 find back」。Headspace 这个姿态抄照搬可行。
- ✅ **用 illustration 的 scale 制造空间感**，不是阴影 / blur——flat vector + 巨大前景人物即可（来源 https://liztran.fyi/headspace:-brand-systems）。
- ✅ **Trust 形态**：把 app 处理过的数据写回系统（Apple Health 集成）作为合法"成果物"，用户分享时不必脱离 app。

### 不适合我们的地方
- ❌ **音频引导全程**——我们做的是验证型工具，没有 Andy 这种真人语料资产，承担不起"全程 voice-led"。
- ❌ **绕开 streak 与 social mechanics**——Headspace 不跑损失厌恶、不跑社交 anchor，结果是重复使用率比 Duolingo 低一档。对于需要"每天都来一下"的学习验证产品，这是个反面警告。
- ❌ **品牌透明度过低**——Headspace 的设计语言被设计学院 / 媒体讨论得少，意味着新用户把这个品牌内化为"reference design"的机会少，对于"我们要做行业参考"而言不利。

## Finch: Self Care Pet

> 资料来源比 Duolingo 少一个数量级，但质量高：两篇 Pratt Institute 学生设计批评、Deepthi J 的 behavioral UX teardown、Revyl Atlas 的 93-screen flow map（这是 Finch 的逆向工程底图）。

### 1. 信息架构与导航
- **底部 tab 共 6 个**（来源：https://revyl.com/atlas/finch/report/ "Tour the bottom tabs" flow）：
  - **Home** — 主仪表盘
  - **Quests** — 每日目标 + 特殊目标
  - **Shop** — 给 pet 换装的商店（Outfit store）
  - **Friends** — 朋友 / buddy 列表（empty state 有 sheet coach）
  - **Bag** — 物品包
  - **Ash** — 自己 pet profile
- **二级 / 抽屉入口（汉堡包）**—— Activities hub（breathing / reflection / goals）、Insights（mood trend / tags）、account、settings、付费墙等等都藏在 hamburger drawer 里（来源同上）。
- **核心任务期间导航**：根据 https://ixd.prattsi.org/2026/02/design-critique-finch-self-care-pet-ios-app/ 与 https://revyl.com/atlas/finch/report/ 的 "Do a Focus breathing session" flow——选 breathing exercise 后进入 intro → setup → active session（一个圆形动画屏幕）→ pause → exit confirm，**底栏和顶栏均不存在或被 dim**，只剩 minimal 控制元素。
- **公开设计文章**：官方**没有 design blog**——Finch 自家没有发表过 system-level design rationale。

### 2. 一次核心会话的状态机
- **核心会话 = "Energize Ash to MAX" loop**（来源：https://revyl.com/atlas/finch/report/）：

  - Tap home → see goal list (today's goals)
  - Tap goal → action sheet (mark done / edit / delete)
  - Mark done → 宠物 gain energy animation + rewarding chime + 微型角色反馈（如 "Your Finch feels calmer"）
  - 编辑 goal → edit sheet → discard-changes dialog
  - 全部完成 → "Ash energized to MAX" reward sheet
  - 然后 进入"today's adventure"——一个 staged narrative 任务，结束后跳 notifications prompt

- **Breathing session**（同上 URL）：
  - Open Activities > Breathe → 选 category（Focus / Calm / Anxiety / Panic / Relaxation）
  - Intro modal → setup → active session（圆形呼吸动画）→ pause → exit confirm
  - 多数 Calm 类练习被 Plus 订阅锁住

- **Reflection**：
  - Drawer > Activities > Reflections → Calm category → prompt → editor → save → reward sheet

- **退出后状态**：完成的目标会持久化为 already-completed，多次重复打卡在同一天通常不会被奖励多次（具体逻辑**不确定**，但 goal 复选行为在两篇 Pratt 批评里都被提到"可视化反馈不稳定"——有时候 writing a reflection 不触发动画）。
- **来源**：https://www.ixd.prattsi.org/2025/09/design-critique-finch-ios-app-2/ 直接写"Journaling entries, for example, sometimes fail to trigger animations, leaving users unsure whether their input was recorded."

### 3. 反馈与动效
- **小动画系统**——颜色 + 角色情绪 + 屏幕级 dot animation，根据 https://medium.com/@deepthi.aipm/ux-teardown-finch-self-care-app-18122357fae7：
  - 完成的可见反馈：宠物 gain energy / 表演欢乐动画 / 角色播报 "Your Finch feels calmer"
  - 颜色：blue / pink / yellow 系浅色调（Finch 用 pastel，不是 Duolingo 高饱和），具体 hex **不确定**。
- **小动画时长 / 缓动**：官方未公布；公开 teardown 都没给具体 ms。
- **复检一种普遍批评**：完成 action 与 visual response 的**映射不稳定**——有时 action 不会被庆祝动画确认（来源：Pratt 2025-09 article）。
- **声音**：chime / soft ping（具体频率**不确定**）。

### 4. 首次使用与空状态
- **Onboarding**：**45 屏**（来源：https://revyl.com/atlas/finch/report/）"Welcome → egg picker → phone verify → pronouns + name + trait → self-care primer + quiz → ABOUT YOU / ENERGY / HOW'S LIFE / SUPPORT AREAS survey → paywall → attribution → buddies + contacts prompt → streak commitment → widget prompt → Home."
  - **关键事实：onboarding 里即插入 paywall**——这是 Revyl 唯一记录到的"early paywall"案例，对我们的研究意义重大。
  - 另外 onboarding 包含一个 self-assessment："Have you used Finch before?" 等问卷，加 5-category 量表（energized / mood / life / support areas）。来源同上。
- **空状态**：Friends tab empty state 有 coach sheet（首次进入会有半透明 sheet 提示如何加朋友），但 Friends 主页在 dismiss 后才显示（来源同上）。
- **首次 streak commitment**：onboarding 末会问你"打算连续打开几天"——这是把承诺搬到首日的 social contract。**公开评论未给具体文案**。

### 5. 留存循环
- **核心 loop = 「energy pet + adventure」**（来源同所有上述 Finch 材料）：
  - 每完成 goal → pet 能量 +1 → 达到 MAX → 解锁 today's adventure → 完成后给"rainbow stones"作为奖励
  - Rainbow stones 是 Finch 的货币单位，能用来买 outfits
- **Streak commitment**：用户首日主动 commit，破坏承诺时被罚。这与 Duolingo 不一样——你主动选择维持多严格，而不是被默认推上 daily hook。
- **Friends / buddies**：friends tab，可加 friends 一起完成任务。**具体的社交机制细节（leaderboard？buddies mutual？）公开材料不够，不确定。**
- **Pause / self-compassion tone**：从 Deepthi teardown 提取，Finch 的失败状态用 "supportive onboarding + first-session flow"——UI 把失败包装为 "you took care of yourself; even small steps count"，而不是 Duolingo 的 guilt-trip。这一点**与 Duolingo 公开思路相反**：Duolingo 损失厌恶最大化，Finch 反而减低焦虑。
- **"Pricing tension"批评**（来源：https://medium.com/@deepthi.aipm/ux-teardown-finch-self-care-app-18122357fae7）：
  - 用户评论："I would gladly pay €15, but €80 a year is too much for the small benefits"（Lluc, 2025-06-26）
  - 用户评论："since the recent update it keeps closing and freezing"（Rebecca, 2025-06-27）
  - 这两条用户真实负评意味着：① 订阅对"温柔"产品太重；② app crash 一次就破灭了 emotional safety。
- **公开 behavioral 设计原理**：**没有**。Finch 没有 design blog 或 research share。

### 6. 文字与语气
- **品牌人格**：「warmth without judgment」+ "self-care best friend"（来源：https://finchcare.com 自述 "Your New Self-Care Best Friend"）。
- **Voice sample**：
  - 上线标语："Daily self-care is finally fun — take care of your pet by taking care of yourself!"
  - "egg picker" 替代 "subscribe"
  - "Your Finch feels calmer"（来自 feedback）—— 语气是第三人物陪伴的温柔
- **公开 voice & tone 指南**：**没有**。

### 7. 设计系统
- **官方 design system**：**没有**。
- **已知的部分 token**：pastel 调色（具体 hex 不确定，公开报告中只见描述）+ 软圆角 + cute character 大量插画。
- **插画角色**：「Birb」（来源：https://ixd.prattsi.org/2026/02/design-critique-finch-self-care-pet-ios-app/）：用户自定义颜色 + 名字 + pronoun + 性格（好奇 / 同情等）。Birth 比雌雄鸟更接近 Tamagotchi meta，跨文化效果更好。
- **Widget**：Finch 提供了 widget——onboarding 期间主动 push 你到 iOS Home 装 widget（来源：https://revyl.com/atlas/finch/report/ widget prompt screen）。**这是个聪明的小 buff——减少了"我今天还没打开 app"的 check 摩擦。**

### 8. 被批评的地方
- **可信批评**：
  - **Onboarding 太重**：第 1 屏到 home 共 45 屏，**包含 paywall + phone 验证 + 心理问卷**——大量自定义 + 大量"我得先告诉你我现在的状态"，违反 progressive disclosure（https://ixd.prattsi.org/2025/09/design-critique-finch-ios-app-2/）。
  - **Home 屏 clutter**：dashboard 把核心 tasks / shop / journeys / community / premium upgrade 并列在同屏，主操作模糊——Pratt 设计批评原话："users may struggle to locate the correct action among multiple competing options, widening the Gulf of Execution"（https://ixd.prattsi.org/2026/02/design-critique-finch-self-care-pet-ios-app/）。
  - **Affordances 的 politics**：\ud83d\udd8e 核心 care 工具（extended reflections / guided journeys）被 paywall gate，wellness **contingent on ability to pay**——这是 Davis 的 affordance 框架下的伦理瑕疵（https://ixd.prattsi.org/2025/09/design-critique-finch-ios-app-2/）。
  - **Mood 选项限制**：预设情绪 category 太 rigid，"restless but hopeful" 的人对不上（Pratt 2025-09 引用 Norman 的 constraints 理论，反向用法）。
  - **可靠性**：用户真实评论"since the recent update it keeps closing and freezing"——对一个**emotional safety**产品，一次崩溃就是品牌损伤（Deepthi teardown）。
  - **价格反 relational 价值**："€80 a year is too much for the small benefits"——价格结构与产品人格矛盾。
- **不存在设计系统**：另一个隐蔽批评——研究 / 复盘 / 复刻 Finch 的开发者 / 设计师难以从公开资料得到 token 级别信息。

### 可偷的模式（直接可执行）
- ✅ **"Tamagotchi 是 universal 概念"的展开点**：用「喂养一个 virtual creature」做最轻量 onboarding，不需要文字即可让用户知道目标（"feed to thrive"）。来源 https://ixd.prattsi.org/2026/02/design-critique-finch-self-care-pet-ios-app/
- ✅ **完成动作 ↔ 情绪反馈的闭环文案**：每次成功都用「Your birb feels calmer」这种第三人物表达，不要 LLM 化（"Here is your reward +5 XP"）。依据：https://medium.com/@deepthi.aipm/ux-teardown-finch-self-care-app-18122357fae7
- ✅ **Widget 主动引导用户装**：减少"今天先看一眼" 的决策成本。来源：https://revyl.com/atlas/finch/report/ widget prompt flow
- ✅ **失败状态用陪伴，不用 guilt**：把"missed day"换成 "your friend is sleeping, come back when you can"，是 Duolingo 思路的明确反面——但可能更适配 wellness / 验证型。
- ✅ **Onboarding 给一个 multi-step commitment screen**（"打算连续打开几天？"）把 streak 责任前置给用户，而不是事后：Finch 的方式更尊重用户主权。

### 不适合我们的地方
- ❌ **45 屏 onboarding 含 paywall**——对学习验证型产品，3 屏以内到核心问题是必须遵守。
- ❌ **6 个底 tab**——我们的功能集没那么宽。
- ❌ **Pastel / Birb 美学**——视觉资产不通用，做学习验证会显幼稚。
- ❌ **无官方 design system**——Finch 不公开 token，意味着第三方的复刻工程成本高，不应作为"标准化基础设施"榜样。
- ❌ **Friends / community 是空状态主导**——我们的产品没有 friend-based retention 这个机制，抄不来。

# 三款共有的交互原则（带证据）

> 这些规则被三款分别以不同强度应用，是"习惯养成型产品"的最大公约数，可作为我们 V1 的设计 checklist。

1. **在「核心任务」期间，能隐藏导航就隐藏导航**——Duolingo 撤掉全部底 tab 只留进度条（https://blakecrosley.com/guides/design/duolingo）；Headspace 在 meditation playback 期间只留 pause/close（隐含性，来自 https://apps.apple.com/us/app/headspace-sleep-meditation/id493145008 的 feature list 只列"play + breathe"，未列 tab）；Finch 在 breathing session 期间退到 single-screen mode（https://revyl.com/atlas/finch/report/ "Do a Focus breathing session"）。**反例**：在「核心任务」阶段，用户正在做的微操作 95% 都在一层屏上，没人需要 4 层的层级。
   - **可执行规则**：核心任务的"理想交互谱" = 1 屏 1 动作，session 完成 → 才回 tab 导航。

2. **失败/退出状态的设计人格 = 「产品主张的倒影」**——Duolingo 的 streak 主张"持续性"，所以失败的语义是"损失"（alert + flame urgency）；Headspace 的主张"温柔"，所以失败的语义是"放过自己"（404 文案那种 big inhale）；Finch 的主张"陪伴"，所以失败的语义是"朋友还在睡觉"。来源：三款各自的 narrative design。
   - **可执行规则**：先写下"我产品的核心人格形容词 3 个"，再写出"用户错过一天时你的空状态文案应该是什么"——人格必须一致。

3. **Onboarding 是"首次信任合同"，不是教学场**——Duolingo "play first, profile second"（https://www.925studios.co/blog/duolingo-design-breakdown），Headspace 引导以"心智状态 + 意图"分类开始（隐含），Finch 把 pet 创建留给 onboarding 最后让用户亲自给 bird 取名（https://www.ixd.prattsi.org/2026/02/design-critique-finch-self-care-pet-ios-app/）。
   - **可执行规则**：onboarding 越早进入"一次小成功"越好。Finch 的 45 屏含 paywall 是反例。

4. **一次完整的反馈必须做 4 件事：颜色 + 动效 + 文案 + 角色**——Duolingo 是这套的极端化：Duo 表情 + 颜色 + 进度条 + "Got it" 文案（https://blakecrosley.com/guides/design/duolingo）；Finch 用 pet 表情 + 颜色 + 文字气泡 + animation（https://medium.com/@deepthi.aipm/ux-teardown-finch-self-care-app-18122357fae7）；Headspace 用品牌 illustration + 简短的语音 + 颜色（https://www.headspace.com/about 404 文案 = 一次"呼吸反馈"）。
   - **可执行规则**：每个核心动作完成时强制清单 = `[色彩反馈] [动效反馈] [单行文案] [角色表情/声音]`。缺一项就会显得"冷淡"。

5. **Streak 是底牌，但 streak 的设计 = 损失厌恶，是双刃剑**——Duolingo 把 streak 维护门槛降到"完成一节课"（+40% 长 streak 用户），但仍保留 loss aversion；Headspace 不跑 streak；Finch 让用户主动 commit 维护长度，把责任转给用户。来源：https://blog.duolingo.com/improving-the-streak/ + https://medium.com/@deepthi.aipm/ux-teardown-finch-self-care-app-18122357fae7
   - **可执行规则**：如果照搬 streak，**必须**提供"主动暂停按钮" + "软重启机制"——否则会因为用户流失反而被反向惩罚成"劣等学习工具"。Headspace 不跑 streak 也能生存，对我们 V1 是更稳的起点。

## 资料缺口（避免外推）

- Duolingo 的 motion spec（具体动画时长 / 缓动曲线完整列表）**没有公开**——只有 Blake Crosley 的非官方复刻。
- Headspace 的 mobile app 当前导航 tab **未在公开材料抓到**——只能从 Web 菜单 + App Store feature 块推断。
- Finch 没有官方设计 blog / voice & tone 指南，只有第三方拆解与一款逆向工程工具（Revyl）。
- 三家的「按钮按下」具体触觉反馈（haptic pattern / 震动）公开材料**没有**。
- 三家会话中断 → 重入时的精确状态恢复机制**不确定**（我们只能靠"进度条仍推进"作间接证据）。
- 用户画像性数据（年龄 / 教育背景）与 UI 设计的对应关系，公开材料**未给出统计性结论**，只给了 baby schema effect 这种心理学假说。

> **结论**：这三款的资料密度差异本身就是一个有用信息——**Duolingo 在 design transparency 上遥遥领先，Headspace / Finch 都把"学习"挡在了门外**。这意味着我们的设计文档如果想成为行业 reference，应主动把 motion / voice / token 都写得比 Duolingo 公开版还细——这是它给同行留的机会。
