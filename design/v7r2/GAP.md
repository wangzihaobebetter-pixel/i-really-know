# 我们 vs 他们：同一把尺子量出来的差距

同一个探针（`probe-shared.cjs`）量了 10 个真实产品和我们自己的 4 个屏。
下面每一条都是**数字对数字**，不是感觉。原始数据：`measure/measurements.json`、`measure/ours.json`。

---

## 1. ⛔ 最严重的一条：这个产品最想要的行为，按钮最小

我们「过一遍」屏上的可点元素实测：

| 元素 | 实测尺寸 | 是什么 |
|---|---|---|
| 麦克风 | 52 × 52 | 语音输入 |
| 提交（↑ 图标） | 52 × 52 | 提交答案 |
| 多看一点原文 | 84 × 40 | 展开原文 |
| 先离开 | 80 × 40 | 退出 |
| **这题我会卡住** | **78 × 19** | **承认答不出来** |

Khan Academy 同类屏的对照：**`[Skip 44×40]` 和 `[Check 130×40]` 并排在常驻底栏里，同等地位。**

这个产品的整个论点是「诚实地承认哪句话没站住」。而**「我卡住了」是全屏最小的命中区（19px 高，
低于 iOS 44pt 最小值的一半）**，就摆在一个 52×52 的提交钮旁边。
界面在用尺寸告诉学生：*瞎编一个答案比承认卡住更容易*。而瞎编正是这个产品唯一不能容忍的行为。

**这不是配色问题，是这个产品目前最大的设计缺陷。十个方案里必须至少有一个把它当作核心命题来解。**

## 2. 「还剩多少」讲得比 Khan 更含糊

我们用一条分段进度条（`.v5-run-progress`，每段 ≥20px 宽）。
Khan 用的是底栏里一句白话：**"Do 4 problems"**。
一句话比一条条纹信息量更高，也不需要用户去数格子。我们连"还剩几问"都要靠数。

## 3. 字号：我们的辅助文字比同类更小

| 产品 | 正文 | 辅助 | 最小 |
|---|---|---|---|
| Khan | Lato 16/22 | 13.1/19.7 | 13.1px |
| Quizlet | hurme 16/24 600 | 14/20 600 | 12/16 600 |
| Headspace | Apercu 16/24 | 12/13.8 500 | 12px |
| Speechify | diatype 16/24、18/24 | — | 16px |
| Notion | Inter 14/20（UI）+ **Lyon Text 18/28（正文衬线）** | 14/20 | 14px |
| Blinkist | CeraPRO 16/24 + 衬线阅读体 | 14/36 | 14px |
| **我们** | Inter 15–16/23–25 | 13/20.8、12/18.6 | **11/17 (760 字重)** |

我们有 **11px + 760 字重**的文字在跑（`.t-micro`）。同类里最小的是 12px，而且多是 500–600 字重。
**11px 加超粗是两个方向同时用力**：字号在退，字重在冲。这是排版层级没定清楚的症状。

## 4. 动效：我们其实是对的，值得写下来

| 产品 | 声明的过渡 |
|---|---|
| Khan | `.125s ease` / `.1s ease-in-out` |
| Speechify | `.15s cubic-bezier(.4,0,.2,1)`、`.08s` |
| Headspace | `.15s` 和 `.4s`，**自定义 `cubic-bezier(.32,.94,.6,1)`** |
| Quizlet | `.12s cubic-bezier(.47,0,.745,.715)` |
| Notion | `.2s cubic-bezier(.42,0,1,1)` |
| Duolingo | `.3s / .4s cubic-bezier(.22,1,.36,1)` |
| **我们** | `.12s / .18s / .26s cubic-bezier(.2,.7,.2,1)` |

我们落在 120–260ms，和严肃学习类产品（Khan 125ms、Speechify 150ms、Quizlet 120ms）同档，
只有游戏化最重的 Duolingo 用到 300–400ms。**这一条不用改，但方案 01 如果要走 Duolingo 路线，
动效必须一起变长到 300ms 以上，否则"厚握感"是假的。**

## 5. 圆角：同类的分布比我想的更极端

- **Blinkist 主圆角是 2px**（74 处），不是大圆角——它的柔软来自颜色和衬线，不是形状
- **Headspace 是 16/32/50%**，圆到接近药丸
- **Khan / Notion 是 4–8px**，克制
- **Brilliant 是 9999px（32 处）+ 17px**，药丸按钮 + 中等卡片
- **我们是 12/15/16/18/999px** —— 中庸，没有立场

**「圆角是有立场的」**：2px 说克制，32px 说温柔，9999px 说可点。我们现在哪句都没说。

## 6. 常驻元素：我们只有一条 68px 的 tab 栏

| 产品 | 常驻的东西 |
|---|---|
| Speechify | 底部 156px 常驻控件栏 |
| Brilliant | 底部 242px 面板 + 顶部 54px |
| Headspace | 底部 346px 区块 |
| Quizlet | 顶部 sticky 120px |
| Khan | **底部常驻操作栏，承载 Skip + Check** |
| **我们（今天）** | 底部 nav 68px |
| **我们（过一遍）** | 底部 102px 答题坞（这个是对的） |

我们的答题坞确实是 fixed 的，102px 高——**方向对，但里面的层级错了**（见第 1 条）。

---

## 这份差距对十个方案的约束

1. 至少一个方案必须**把「我卡住了」升级成和「提交」同级的一等动作**，并把它作为该方案的核心论点。
2. 至少一个方案必须**用一句白话代替进度条**说清还剩多少。
3. 排版必须**定一个最小字号并守住**（建议 ≥12px，且 12px 处不许再用 700+ 字重）。
4. 圆角必须**选一个立场**（2px 克制 / 8px 中性 / 16px 温和 / 32px 柔软 / 药丸），不许中庸。
5. 动效要和方案的性格绑定：严肃 = 120–150ms，游戏化 = 300–400ms。**不许所有方案共用一套时长。**
